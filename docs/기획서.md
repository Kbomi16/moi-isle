# 모이섬 기획서

> 이름을 고르고 섬에 들어온다. 걷고, 사람을 보고, `/`로 말하고, 내 방을 꾸민다.

작성일: 2026-09-22  
상태: 초안 (1차)

---

## 1. 한 줄

모이섬은 Three.js로 만드는 **작은 소셜 마을**이다.

브라우저를 열고 이름, 직군, 모습을 고르면 섬에 선다.  
같은 땅에 누가 와 있는지 보이고, `/`로 한 줄을 주고받고, 내 방에는 나를 보여 주는 자리만 둔다.

게임·상점·수집은 만들지 않는다.  
성공은 “예쁜가”가 아니라 **들어와서 말하고, 방을 만져 볼 수 있는가**다.

---

## 2. 왜 만드는가

혼자 걷는 3D 장면은 이미 많다. 모이섬이 하려는 일은 장면이 아니라 **동석**이다.

- 섬이 작아서, 멀리 가지 않아도 사람이 보인다.
- 걷다 보면 자연스럽게 마주친다.
- 마주치면 바로 말할 수 있다.
- 내 방은 전투나 점수가 아니라, 가구·기술·짧은 글로 나를 남기는 자리이다.

이름은 그대로 **모이면 섬**이다. 세계관 소설을 쓰지 않는다.

---

## 3. 한 번의 방문

```text
이름·직군·모습 → 마을 → / 로 말하기 → 내 방
```

1. **고른다**  
   닉네임, 직군, 준비된 모습 중 하나를 고른다.  
   튜토리얼, 계정 로그인은 없다.

2. **들어온다**  
   마을에 선다. 랜드마크와 주민 몇이 이미 있다.  
   다른 접속자가 있으면 그 모습이 같은 땅에 움직인다.

3. **말한다**  
   `/`를 누르면 입력창이 열린다. 화면에서 채팅 패널을 찾지 않는다.  
   상시 채팅 창, 채널, 귓속말은 없다.

4. **방으로 간다**  
   내 방에서 가구를 놓고, 기술스택을 붙이고, 방명록을 남긴다.  
   이 세 가지 외에 방 안 기능은 두지 않는다.

이 네 박자가 동작하면 1차는 성공이다.

---

## 4. 입장

입장 전 화면은 마을을 보여 주지 않는다. 전체 화면에서 세 가지를 고른다.


| 단계  | 내용                         |
| --- | -------------------------- |
| 이름  | 닉네임 한 칸. 비어 있으면 들어가지 못한다. |
| 직군  | 프론트·백엔드·풀스택·모바일·UI/UX·PM·서비스기획·데이터·인프라·QA 중 하나. |
| 모습  | 준비된 아바타를 넘겨 보며 하나 고른다.    |
| 입장  | 고른 이름과 모습으로 마을에 선다.       |


하지 않는 것: 이메일 로그인, 아바타 에디터, 직군 직접 입력.

---

## 5. 마을

섬은 콘텐츠 창고가 아니라 **만남의 마당**이다.

- 공간은 **마을**과 **내 방** 두 장뿐이다.
- 한 카메라에서 윤곽이 보이는 크기. 가장자리까지 걸어갈 수 있다.
- 지형은 풀과 길, 낮은 언덕. 점프·낙하·던전은 없다.
- 주민 NPC를 **소수** 둔다. 자리와 실루엣이 목적이다. 퀘스트·상점·전투는 없다.
- 다른 접속자는 같은 마을에서 걷는다. 가까이 가면 닉네임이 읽힌다.
- 이동은 WASD(또는 방향키). 카메라는 뒤를 따른다. 달리기, 클릭 이동, 미니맵은 없다.

마을과 내 방만 오간다. 다른 맵은 만들지 않는다.

---

## 6. 내 방

방은 꾸미기 게임이 아니다. **나를 보여 주는 작은 공간**이다.

방 안에서 할 수 있는 일은 세 가지뿐이다.


| 기능      | 누가         | 무엇을                         |
| ------- | ---------- | --------------------------- |
| 가구 배치   | 방 주인       | 준비된 가구를 바닥·벽에 놓고 돌릴 수 있다.   |
| 기술스택 배치 | 방 주인       | 스택을 벽에 붙여 무엇을 다루는지 보여 준다.   |
| 방명록     | 그 방에 있는 사람 | 짧은 글을 붙여 남긴다. 작성자와 시각이 보인다. |


다른 사람 방에도 들어갈 수 있다.  
남의 방에서는 가구와 스택을 건드리지 못하고, 방명록만 남긴다.

하지 않는 것: 집 짓기, 인벤토리, 화폐, 제작, 방 크기 변경, 조명 편집.

---

## 7. 대화 — `/` 한 줄

대화는 기능이 아니라 만남의 연장이다.  
피그마에서 `/`를 누르듯, 입력창을 찾아다니지 않는다.

- `/` : 입력창을 연다. 포커스가 바로 간다.
- Enter : 보낸다. 창을 닫는다.
- Esc : 보내지 않고 닫는다.
- 표시: 캐릭터 위 말풍선. 긴 로그 창은 두지 않는다.
- 범위: 같은 마을에 있는 사람에게 실시간으로 간다. 확성기형 공지 UI는 만들지 않는다.

입력창이 열려 있는 동안 WASD는 잠시 멈춘다.

---

## 8. 실시간

다른 사람이 같은 땅에 보이고, 말과 방이 맞춰져야 하므로 **1차부터 웹소켓을 쓴다.**

서버는 접속자 목록을 메모리에 둔다. 계정과 DB는 다음이다.


| 이벤트          | 방향      | 역할                             |
| ------------ | ------- | ------------------------------ |
| `initialize` | 양방향     | 닉네임·모습으로 나를 등록하고, 내 상태를 받는다.   |
| `players`    | 서버 → 전원 | 위치, 닉네임, 모습, 방 상태 목록.          |
| `enter`      | 서버 → 전원 | 누가 들어왔는지 짧게 알린다.               |
| `exit`       | 서버 → 전원 | 누가 나갔는지 짧게 알린다.                |
| `move`       | 클라 → 서버 | 내 위치를 보낸다. 서버가 `players`로 뿌린다. |
| `newText`    | 양방향     | `/`로 보낸 한 줄.                   |
| `myRoomChange` | 클라 → 서버 | 가구·스택·방명록이 바뀌면 그 방 상태를 덮어쓴다. |


MVP에서 방은 **서버가 켜져 있는 동안만** 유지된다.  
서버를 끄면 배치는 사라질 수 있다.

동시 접속은 **소수**를 전제로 한다. 광장 서버가 아니라 작은 마당이다.

---

## 9. 기술

이미 고른 프론트 스택을 유지하고, 실시간만 서버로 붙인다.


| 구분  | 선택                                      |
| --- | --------------------------------------- |
| 런타임 | Bun                                     |
| 앱   | Vite + React + TypeScript               |
| 3D  | Three.js + React Three Fiber + Drei     |
| 실시간 | Socket.IO                               |
| 상태  | 클라 로컬 + 서버 메모리의 접속자 목록                  |
| 에셋  | `.glb` / `.gltf`, CC0 또는 출처 표기 가능한 라이선스 |


에셋은 `public/models/`에 두고, 출처는 `docs/credits.md`에 남긴다.  
직접 하이폴리 모델링은 하지 않는다.

---

## 10. 화면과 조작

- 입장 전: 이름, 직군, 모습. 마을 없이 전체 화면.
- 입장 후: 마을이 화면을 채운다. HUD는 얇게. 힌트는 `/`, WASD, 내 방뿐이다.
- 내 방: 가구 / 기술스택 / 방명록 툴만 둔다.
- 이동: WASD / 방향키. 마우스로 카메라 궤도를 살짝 돌릴 수 있다.

UI는 섬을 가리지 않는다. 오른쪽을 채우는 채팅 패널은 쓰지 않는다.

---

## 11. 톤

- 낮, 맑음, 풀과 길. 과한 네온·사이버펑크·공포 연출은 쓰지 않는다.
- 카피는 짧게. 반말 세계관이나 설정 더미를 쓰지 않는다.
- 말풍선과 입력은 짧게, 귀엽게. 게시판처럼 보이지 않게 한다.

---

## 12. 성공했는지 보는 법

구현이 아니라 경험으로 본다.

1. 이름, 직군, 모습을 고르고 1분 안에 마을에 설 수 있는가.
2. 주민과, 있다면 다른 사람 실루엣이 보이는가.
3. `/`를 눌러 한 줄을 보내면 말풍선이 뜨는가. 다른 브라우저에도 보이는가.
4. 내 방에서 가구·스택·방명록만으로 방을 손볼 수 있는가.
5. 상점이나 퀘스트가 없어도, 이 섬에 서 있는 느낌이 남는가.

5번이 아니면 기능을 더하지 말고, 마을·거리·말풍선·방 툴을 고친다.

---

## 13. 구현 순서

1. 입장: 닉네임 + 직군 + 모습 선택.
2. 마을 맵 + 주민 소수. WASD 걷기.
3. 서버: 입장, 접속자 목록, 이동, 들오고 나감.
4. `/` 입력창 + 말풍선 동기화.
5. 내 방: 가구·기술스택·방명록. 방 상태 반영.
6. 다른 사람 방 방문. 방명록만 쓰기.
7. 에셋과 출처 정리.
