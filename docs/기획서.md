# 모이섬 기획서

> 작은 섬에 들어와, 걷고, 만나고, 이야기한다.

작성일: 2026-09-05  
상태: 초안 (MVP 기준)

---

## 1. 한 줄

모이섬은 Three.js로 만드는 **소셜 마을**이다.  
다른 사람이 같은 섬에 들어와 걷고, 가까이 가서 대화하는 것이 전부이자 목표다.

꾸미기 게임이 아니다. **사람이 와서 만나는 곳**이다.

---

## 2. 왜 만드는가

혼자 있는 3D 장면은 이미 많다. 모이섬이 하고 싶은 일은 장면이 아니라 **동석**이다.

- 작은 섬이라서 멀리 가지 않아도 사람이 보인다.
- 걷다 보면 자연스럽게 마주친다.
- 마주치면 말을 걸 수 있다.

성공 기준은 “그래픽이 예쁜가”가 아니라,  
**다른 사람과 같은 땅에 서 있다는 느낌이 나는가**다.

---

## 3. 레퍼런스 — 모여봐요 동물의 숲

동물의 숲을 그대로 복제하지 않는다.  
가져올 것과 버릴 것을 나눈다.

### 가져올 것

| 요소 | 모이섬에서의 의미 |
| --- | --- |
| 작은 섬 | 한 번에 읽히는 공간. 로딩 없이 바로 마을이 보인다. |
| 3인칭으로 천천히 걷기 | 탐험보다 배회. 뛰어서 통과하는 맵이 아니다. |
| 낮고 따뜻한 낮 분위기 | 과한 네온, 사이버펑크, 공포 연출은 쓰지 않는다. |
| 만남이 콘텐츠 | 상점, 퀘스트, 수집보다 “누가 와 있는가”가 먼저다. |
| 낮은 폴리, 읽기 쉬운 실루엣 | 직접 하이폴리 모델링을 하지 않는다. |

### 지금 가져오지 않을 것

- 무인도 꾸미기, 집 짓기, 가구 배치
- 주민 NPC 루틴, 상점, 도도 항공
- 날짜·계절·수집 도감
- 인벤토리, 화폐, 제작

동물의 숲에서 빌리는 것은 **세계관 시스템이 아니라 만남의 리듬**이다.

---

## 4. 핵심 경험

한 번의 방문은 네 박자로 끝난다.

```text
들어온다 → 걷는다 → 만난다 → 이야기한다
```

1. **들어온다**  
   브라우저를 열고 닉네임을 적으면 섬에 선다. 계정, 튜토리얼, 로딩 연출은 MVP에서 없다.

2. **걷는다**  
   WASD(또는 방향키)로 섬 안을 걷는다. 카메라는 캐릭터 뒤를 따라간다.  
   섬은 작아서, 가장자리에서 반대편이 대충 보인다.

3. **만난다**  
   다른 사람의 캐릭터가 같은 땅에 보인다. 가까이 가면 상대 닉네임이 읽힌다.

4. **이야기한다**  
   일정 거리 안에 있을 때만 채팅이 오간다. 섬 전체에 외치는 확성기가 아니다.

이 네 박자가 동작하면 1차는 성공이다.

---

## 5. 공간 — 작은 섬

- 규모: 한 카메라 앵글에서 섬의 윤곽이 보이는 정도. 워킹으로 가장자리까지 수십 초.
- 지형: 완만한 풀밭, 모래, 얕은 물가. 점프·낙하·던전은 없다.
- 랜드마크: 한두 개면 충분하다. 나무, 부두, 벤치처럼 “여기서 만나자”고 말할 수 있는 자리.
- 경계: 섬 밖으로 떨어지지 않게 막는다. 무한 월드는 만들지 않는다.

섬은 콘텐츠 창고가 아니라 **만남의 마당**이다.  
소품을 많이 놓기보다, 사람이 서 있을 빈 자리를 남긴다.

---

## 6. 캐릭터 — 일단 임시

직접 블렌더로 캐릭터를 만들기 전에, **식별 가능한 임시 몸**으로 만남을 검증한다.

- 형태: 캡슐, 로우폴리 휴머노이드, 또는 무료 캐릭터 메시 하나.
- 구분: 색과 닉네임으로 서로 알아본다. 커스터마이즈는 나중.
- 이동: 걷기만. 앉기, 이모트, 달리기는 MVP 밖.
- 이름: 입장 시 닉네임. 로그인 없음.

임시 캐릭터가 어색해도 상관없다.  
어색한 몸으로도 “저 사람이 나에게 다가온다”가 느껴지면 방향은 맞다.

---

## 7. 에셋 원칙 — 무료 3D를 가져와 쓴다

블렌더로 직접 만들면 좋겠지만, 지금은 만들지 않는다.  
이미 있는 무료 3D 파일을 가져와 섬을 조립한다.

### 쓸 수 있는 것

- CC0, 또는 출처 표기만으로 재사용 가능한 라이선스
- `.glb` / `.gltf` 우선 (웹에서 바로 로드)
- 로우폴리, 작은 용량, 낮 장면에 맞는 색

후보군 예: Kenney, Poly Pizza, Quaternius, Sketchfab의 CC 라이선스 에셋.

### 쓰지 않는 것

- 라이선스가 불명확한 에셋
- 동물의 숲 원본 메시·텍스처·사운드
- 용량이 커서 첫 입장에 방해되는 하이폴리 장면

가져온 파일은 `public/models/` 아래에 두고, 출처와 라이선스는 `docs/credits.md`에 남긴다.  
에셋이 모이기 전이면 단순한 지오메트리로 섬의 비율만 먼저 맞춘다. (현재 스캐폴드가 이 단계다.)

---

## 8. 대화 — 가까운 사람끼리만

대화는 기능이 아니라 만남의 연장이다.

- 입력: 화면 하단 한 줄. Enter로 전송.
- 범위: 보낸 사람 주변 반경 안에 있는 사람에게만 보인다.
- 표시: 캐릭터 위 말풍선 + 가까운 로그만. 전체 채팅 창은 두지 않는다.
- 길이: 짧게. 장문 게시판이 아니다.

멀리 있는 사람에게 메시지가 가면, 섬이 광장에서 게시판으로 바뀐다.  
모이섬은 광장을 고른다.

---

## 9. 다른 사람 — 진짜가 목표, 순서는 나눈다

최종 목표는 **실제로 다른 브라우저가 같은 섬에 들어오는 것**이다.

한 번에 서버·계정·동기화를 다 만들지 않는다. 만남의 감각을 먼저 확인한다.

| 단계 | 무엇이 섬에 있나 | 확인하는 것 |
| --- | --- | --- |
| 0 | 나만 있다 | 섬이 작고, 걷기가 느긋한가 |
| 1 | 더미 방문객이 걷는다 | 다가가면 닉네임이 읽히고, 가까워지면 말하고 싶은가 |
| 2 | 실제 다른 사람이 들어온다 | 위치와 짧은 말이 같은 땅에 남는가 |

실시간 동기화(위치, 닉네임, 근접 채팅)는 2단계에서 넣는다.  
음성, 친구 시스템, 방 목록, 대규모 인원은 그 다음이다.

동시 접속은 한 섬에 **소수**를 전제로 한다. 광장 서버가 아니라 작은 마당이다.

---

## 10. MVP와 하지 않을 것

### MVP (이 기획서가 가리키는 1차)

1차의 끝은 **더미 방문객과 근접 대화가 되는 섬**이다.  
실제 다른 브라우저가 들어오는 것은 목표이지만, 1차 밖(2단계)이다.

- 작은 섬 (지오메트리 또는 무료 에셋)
- 임시 캐릭터 + WASD 걷기 + 3인칭 카메라
- 닉네임 입장 (게스트)
- 더미 방문객과 거리 기반 만남
- 근접 텍스트 대화 (로컬에서 더미와 시험)

### MVP에서 하지 않는다

- 직접 캐릭터·섬 모델링
- 집 꾸미기, 상점, 수집, 인벤토리
- 로그인, 프로필, 아바타 에디터
- 음성 채팅, 이모트, 미니게임
- 모바일 전용 조작 (되면 좋지만 필수 아님)

## 11. 기술 방향

이미 고른 스택을 그대로 쓴다.

| 구분 | 선택 | 이유 |
| --- | --- | --- |
| 런타임 | Bun | 로컬 개발 |
| 앱 | Vite + React + TypeScript | 현재 스캐폴드 |
| 3D | Three.js + React Three Fiber + Drei | 섬·캐릭터·카메라 |
| 에셋 | GLB, 무료 라이선스 | 블렌더 작업을 미룸 |
| 멀티플레이 (2단계) | 가벼운 실시간 채널 | 위치와 짧은 채팅만 동기화 |

프론트만으로 0·1단계를 끝낼 수 있다.  
서버는 “다른 사람이 정말 들어올 때” 추가한다.

---

## 12. 화면과 조작

- 전체 화면이 섬이다. 메뉴로 시작하지 않는다.
- 입장 전: 닉네임 한 칸.
- 입장 후 HUD: 닉네임, 짧은 조작 힌트, 근접했을 때만 보이는 채팅 입력.
- 이동: WASD / 방향키. 마우스로 카메라 궤도를 살짝 돌릴 수 있다.
- 점프, 달리기, 클릭 이동은 MVP에 넣지 않는다.

UI는 섬을 가리지 않게 얇게 둔다.  
동물의 숲처럼 정보가 화면을 채우지 않는다.

---

## 13. 톤

- 낮, 맑음, 풀과 물.
- 색은 부드럽고 채도가 과하지 않다.
- 카피는 짧게, 반말이나 과한 세계관 설정은 넣지 않는다.
- 이름 그대로 **모이면 섬**이다. 세계관 소설을 쓰지 않는다.

---

## 14. 성공했는지 보는 법

구현이 아니라 경험으로 본다.

1. 처음 들어온 사람이 1분 안에 섬을 한 바퀴 걷고 “작네”라고 말할 수 있는가.
2. 다른 실루엣이 보이면 다가가고 싶어지는가.
3. 가까이 가서 한두 문장을 주고받을 수 있는가.
4. 그 짧은 만남 뒤에 더 많은 시스템(상점, 꾸미기)이 없어도 아쉽지 않은가.

4번이 아니면 기능을 더하지 말고, 섬·거리·속도·말풍선을 고친다.

---

## 15. 다음에 할 일 (구현 순서)

기획이 가리키는 구현 순서만 적는다. 세부 태스크는 구현 계획에서 나눈다.

1. 지금 스캐폴드 원을, 걷을 수 있는 작은 섬으로 바꾼다.
2. 임시 캐릭터를 넣고 3인칭으로 걷게 한다.
3. 닉네임과 얇은 HUD를 붙인다.
4. 더미 방문객으로 만남·근접 대화를 시험한다.
5. 무료 GLB로 섬과 랜드마크를 교체한다. 출처를 `docs/credits.md`에 적는다.
6. 실제 다른 사람이 들어오게 위치와 말을 동기화한다.
